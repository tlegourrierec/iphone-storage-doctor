# Contributing

## The one rule that is not negotiable

**No heuristic may ever classify a file under `/DCIM` or `/PhotoData` as
deletable.** Removing a photo over AFC leaves its row in `Photos.sqlite`,
which corrupts the library. `tests/test_rules.py` enforces this; a change that
breaks that test will not be merged, whatever space it would reclaim.

More generally, a new rule that deletes must justify *why* the data is
regenerated by iOS. When in doubt, classify it `REVIEW` and let the user decide.

**Every code path that removes data from the device asks the user first.** A
command-line flag is not consent: the user sees what will go and says yes, or
the tool stops. If you add a destructive path, route it through the same
confirmation and cover it in `tests/test_clean.py`.

## Setup

```bash
python3 -m venv .venv
./.venv/bin/pip install -e ".[dev]"
./.venv/bin/python -m pytest -q
```

Tests run without a device connected — they cover the heuristics, not USB
communication. If you change anything that talks to the device, say in your PR
which model and iOS version you tested on.

## Adding a rule

Rules live in `ipsd/rules.py` and are plain functions taking the file
inventory and returning a `Finding` or `None`. Add one to `MEDIA_RULES`, and
add a test that pins both the positive and the negative case — a rule that
never says "no" is a rule that will delete something it should not.

## Device reports are contributions

If you run the tool on a model we have not covered, open a *Device
compatibility report*. iOS changes which lockdown services answer from one
release to the next, and we cannot test every combination.
